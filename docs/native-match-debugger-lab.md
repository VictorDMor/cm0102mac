# Match lab: time, events and unrestricted substitutions

## Delivered behavior

The default **Match** view shows a large original match clock, score, named players and substitutes, and football commentary together. Technical fields remain in **Details**. **Play**, **Pause**, **Back**, **Next moment**, minute jumps and a `minutes:seconds` field control the real engine. The clock converts the original signed field at `match+0x7948` using eleven engine units per minute; its original event-related adjustments remain visible.

Each successful engine call or intervention records a complete process-local guest checkpoint. **Back** restores registers, scratch, mapped memory, allocations, counters, score, actors and the matching event prefix. **Next moment** replays a recorded checkpoint when one exists, otherwise executes the production engine. Seeking within recorded history restores the closest available engine boundary. Seeking beyond it executes real calls and stops at the target or an original pause/completion/abort boundary. The displayed clock is the time actually reached. Playing or editing a past moment discards its obsolete future and begins a new branch. Faulted experiments can recover through recorded boundaries or restart.

Unchanged 4 KiB guest pages are shared between checkpoints. History is held in RAM, with no per-step disk capture or career save. It is not a general operating-system/file-handle snapshot. Normal restart and exit release the private experiment backing. All-club and full-match acceptance remain outside this bounded delivery.

## Events and player controls

The event observer forwards existing memory observations and records only committed original commentary at `10201704`, after the original twenty-byte ring record has received its code, both actor/side pairs and context. Staff identities are captured at that boundary so earlier events keep their player names after replacements. Diagnostic reads use unobserved memory copies and do not add guest effects.

Descriptions use the original English event catalog. The engine event type and actors are observed exactly; readable text uses the first catalog variant whose placeholders can be resolved. It does not reproduce the original random choice of wording. Context-specific phrases fall back to the configured event label and player name. The view shows the most recent 2,000 events in the current branch; the session retains its full recorded event history. Injected goals, injuries and substitutions are labelled **Injected**.

The fresh factory initializes up to nine actual nonstarting club players per side through the same production player preparation used by lineup editing. All club roster members remain available in the replacement chooser, including players outside those nine bench places. Select an on-pitch or injured player, choose a replacement and press **Substitute** while paused after kickoff. The debugger permits more than three substitutions, player re-entry and any replacement position, including an injured goalkeeper. An already active player, the outgoing player itself or a foreign-club player is rejected before any mutation.

Substitution invokes the complete original method `103cb760..103cba60`: 192 indexed instructions, canonical address/assembly/operations/flow/fallthrough SHA-256 `7f7ae3dc7964b4fc8a5afba5d5f1bf95bcb363021e9fbd66d3caf084e8feea46`. Its presentation caller supplies only the owning match at `+4` and side at `+e68`. The original method performs pitch and marking changes, timestamps, counters, roles and commentary. Newly represented roster members use complete production actor preparation first. Injury replacements restore the outgoing role for the original boundary and return an emergency replacement to a vacant role. The existing production goalkeeper cache clear/resolver then refreshes the live keeper.

Unlimited substitutions deliberately grant one original remaining-substitution allowance when exhausted, allowing the original operation to consume it to zero. Bypassing the UI limit without that grant underflowed its signed byte and broke later automatic injury handling; the corrected scenario is covered. This is an explicit debugger policy. Ordinary game substitution rules are unchanged. No additional semantic replacement is claimed; the manifest remains 643 entries.

## Isolated original event polling

Original player preparation occasionally polls progress events. The worker previously entered AppKit through the original game event bridge and could wait for a game window that the standalone process does not own. Its platform now explicitly selects isolated event mode: `WaitNextEvent` and `GetNextEvent` return a valid null event with a live system tick and zero input fields, immediately. The three-argument platform constructor retains ordinary interactive game behavior. Both original import paths are checked with a deliberately long wait request. No football routine is replaced by this host event policy.
