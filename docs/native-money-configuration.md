## Selection, scale stores and six strings

The input is in r3. Selection sign-extends only its low byte, then compares that
word unsigned with 24. Bytes 0..24 are valid; all other byte values take the
original diagnostic path. Thus 256 selects profile zero, while 255 is rejected.
The complete input word is retained in r31, and its low byte is published only
after the selected profile's string copies.

Before the first copy, the prologue caches all six output pointers, the string
bank and the floating-bank pointer. A bounded selection reads the original jump
table, updates CTR and enters direct C++ profile code. Each profile retains its
specific floating register reuse and load/store order, rather than normalizing
all profiles to three independent loads. Three factor stores precede copying:

| Guest setting | Consumer |
| --- | --- |
| `TOC-0x3aec` | Display conversion and conversion back to stored amounts |
| `TOC-0x3af4` | Selection of a preset/table amount |
| `TOC-0x3afc` | Quantum/step selection |

The selected symbol is copied first, followed by ordinary units, thousands,
millions, billions and trillions. Each copy reads its source at that point;
the cached destination pointers do not change when a dependency mutates their
TOC slots. Copying is not replaced by a bulk clear of the buffers. Existing bytes
after the newly written NUL remain observable.

After all six copies, the profile stores the grouping separator, decimal
separator, four-digit grouping preference and selected input byte, then returns
one. Some profiles deliberately use the same separator for grouping and decimal
positions, with a shorter original register-assignment sequence. That sequence
and its residue are preserved.

The original Real profile has display factor 2.73, preset factor 3.0 and step
factor 1.0, with symbol `R$`, ordinary-unit suffix `,00`, grouping point and decimal
comma. Profile 20 leaves its billions suffix empty; the existing numeric
formatter can therefore take its empty-suffix fallback. Profile 21 uses an ASCII
space for grouping. These are historical game constants, not current exchange
rates or new balancing rules.

## Invalid input and access order

Invalid selection calls the four original diagnostic services in order, then
loads the diagnostic-flag pointer from `TOC-0x7bac`, clears its byte and returns
zero. The pointer is read **after** those services. With distinct diagnostic
storage, prior factors and presentation settings remain unchanged; source or
output aliases retain their actual ordered effects.

Invalid selection does not dereference the unused dispatch/floating banks or
output buffers, even if their loaded pointer values are null. Valid selection
does not dereference the diagnostic scratch buffer. Mandatory TOC, profile-bank
and selected output accesses retain their original faults. The routine does not
add host-side validation, a default currency or a recovery policy.
