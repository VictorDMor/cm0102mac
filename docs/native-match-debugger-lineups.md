# Pre-kickoff lineup editing in the match debugger

## Behavior and scope

The **Before kickoff** controls edit a fresh paused experiment. The inspector shows all forty actor spaces, including empty spaces, and exposes each side's actual original club roster. Select an actor, choose an unused club player and press **Set player** to replace a starter or create a reserve in an empty space. Choose **Bench** or a position from 0 through 10 and press **Apply slot** to change the player's starting assignment. Position 0 is the goalkeeper assignment. An occupied position exchanges the selected and displaced players' assignments, preserving unique positions. A reserve taking a starter's slot moves that starter to the bench.

These are pre-kickoff edits. After advancement starts, the existing **Withdraw (injury)** and **Add goal** controls apply their separately characterized interventions. Original fixture rules govern subsequent automatic substitutions; this change adds no in-match substitution control. The editor preserves original unavailable status and rejects assigning unavailable or empty actors to starting positions. A missing goalkeeper or invalid/duplicate starting position prevents Step/Run before any engine write; the experiment remains paused for correction.

Accepted edits log actual staff IDs, actor/side, position changes, a displaced actor where applicable, active-player counts and instruction cost. Editing does not count as a completed engine step. Reset returns to the fresh original club/seed setup and clears player, position, withdrawal and goal interventions. Failed creation still preserves the previous experiment.

## Original construction and ownership

The original isolated fixture initializes eleven populated actors per side. Other spaces have no staff reference and original position `-5`; treating an empty space as an existing reserve is invalid. A characterization negative that swapped the goalkeeper into such an empty actor reached an original null-data fault. The delivered editor validates presence and constructs an actual actor instead.

`EngineInstance` retains the two resolved original roster vectors from its fresh `DatabaseWorld`, alongside the state that owns their staff/player references. No career or captured-match data supplies candidates. The API accepts a staff ID, validates its membership and resolved player pointer against that side's original roster, and rejects an already assigned player before any guest write. Empty rows display no staff ID; the UI offers unused real club players.

**Set player** invokes complete original preparation `1020e8f0(controller, actor index, staff pointer, actor index)`, where the live controller is `match+0x7aac+side*0xd8`. It invokes full original actor initialization `10223ac0`, populating the real staff/player identity, attributes, condition, side/club context and original actor number. Both index arguments retain the original actor identity used by commentary; a replacement then restores its prior valid position through the reconstructed position setter. A healthy replacement for an unavailable actor starts benched. Original unavailable results remain unavailable. Empty reserve actors retain the constructor's original bench result.

**Apply slot** uses the production position setter `101f1870`, already reconstructed in C++23. It updates a displaced player first and then the selected player, within one bounded paused edit. First advancement builds and uses the original pitch state from these live assignments. A write failure or budget interruption retains partial guest effects, restores the caller budget, records no accepted edit and faults the session until reset.

The complete original preparation body contains 66 instructions (`1020e8f0..1020e9f8`); its actor initializer contains 2,712 (`10223ac0..10226520`). Their canonical source fingerprints are retained privately for the next C++23 reconstruction block. **Both construction bodies remain original dependencies in this delivery. The semantic manifest remains 604.** The host/session/UI additions are C++23/Objective-C++; this is not acceptance of the complete actor initializer as reconstructed code.

## Focused evidence and limits

Two independent actual Arsenal/Manchester United worlds compare two complete player constructions and seven position edits against direct original calls. Checks cover the complete match record, all register/unique bytes, return PC, allocations/free maps, restored budgets, exact instruction/import accounting from the initialized-match boundary and ordered map/clear/write effects. The first operation constructs actual Patrick Vieira as reserve actor 11: 1,513 instructions and 301 effects. An away starter replacement uses 1,597 instructions and 307 effects. A staff-pointer-only negative differs from each full original construction.

Reserve promotion, displaced-player benching, position restoration, removal from the starting side and goalkeeper correction agree with the original. Thirty subsequent original shared-engine calls agree with C++23 shared advancement in full match state/accounting and retain the edited ten-player home lineup. C++23/original position-setter counters are nonzero. Rejected foreign/duplicate/missing players, invalid indices/positions, empty actors, unavailable edit boundaries and missing-goalkeeper Step/Run preserve state/history. A forced budget stop just after the real staff store preserves an inspectable fault without an accepted edit or completed step; another experiment remains unchanged. Seeded reset removes the added reserve and all lineup edits.

The actual worker protocol covers full actor/roster presentation, reserve creation, promotion/displacement, benching/restoration, before/after logs, strict Boolean/fractional/out-of-range commands, late-edit rejection, goals/withdrawal and subsequent execution, independent club pairings, reset and normal EOF/exit/backing cleanup. Release and UBSAN session/factory/lineup-harness checks pass with identical output and empty sanitizer stderr; remaining dependencies are not newly instrumented. Interactive installed-control verification is tracked separately. Owned probes, linked checks, sanitizer objects and experiment backings are removed after this cycle. Original game data and career files are preserved. Save/Load is **not retested**; performance is **not benchmarked**.
