## Distribution among clubs

The distribution entry takes the shortlist object, staff pointer and a signed
low-byte force flag in r3 through r5. It requires a profile; without the force
flag, the signed halfword at profile+10 must be at least 5,500. Further guards
inspect the staff-status byte, staff kind, associated records and the original
pending-transfer service. Stored-club and date conditions can query the primary
contract, its status nibble and another field before allowing distribution.
The date helper receives a 200-day subtraction; its resulting comparisons and
same-year signed arithmetic are preserved rather than replaced by a new policy.

The operation publishes its primary-contract query to the existing scratch
global, resolves the contract's club and reads the upper metadata nibble as its
starting count. Role qualifications retain five original implications:
`2 -> 4`, `8 -> 16`, `32 -> 16`, `128 -> 256` and `2048 -> 1024`.
These are bit relationships; this report does not infer UI position names.

The original club-order array is scanned until the count reaches five or the
club population ends. The current iteration's club ID and record are read before
the count guard, preserving positive pointer faults even when a count is already
at its limit. The operation skips clubs rejected by a service, the primary
contract club and the staff's stored club. It calls the selected registration
body for each remaining club and increases its local count when that body's
signed low-byte result is nonzero. Counts, array ordering and return residues
retain the original ABI; the distribution operation has no newly normalized
boolean return.

## Two paths through the forty club rows

Both registration operations resolve original contract context, require the
club entry's status byte to be one and its +9 counter to be below 100, then query
the existing staff/club pair index. A duplicate returns one without creating a
second link. If registration proceeds, the original eligibility and transfer
services are consulted before the forty-row scan. The automatic path also has
club-policy, profile and financial-service prerequisites.

Rows are filtered by kind eleven, an unused secondary reference, qualification
bits, reference combinations, dates and the +0x28 flag/category field. The
automatic path additionally rejects a zero qualification mask. Category five
has a signed low-byte threshold of 24 from staff+0x5c, affiliation comparisons,
profile thresholds and a shared random sequence. These raw fields are not
assigned unconfirmed UI labels. The automatic path uses a profile threshold of
1,000 and a draw modulo 2,000 plus 1,000; the requested path uses 5,000 and a draw
modulo 1,000 plus 500. Prefetch, refill, salt, signed arithmetic and call order
remain distinct and exact.

Previous and candidate staff are assessed through external services. The
automatic path can tentatively replace row+8 using `0.01536 * row+4 * row+4`
with the original single/double rounding and integer conversion sequence, capped
against another financial result. Later paths may restore the saved value or
retain the partial write. Independent assertions distinguish a rejection that
restores the starting value of 10,000 from an earlier rejection that leaves the
changed threshold. No universal rollback was added.

Both operations calculate contribution weights, retain their 0.01 and 3.0 bounds
and apply `0.67 + weight / 3` on the path above one. Their denominators differ:
the automatic path uses a normalized row threshold and a club-field scale; the
requested path uses the original signed arithmetic derived from the square of
club+0x1ec. Related paths also deduct the square of an attribute's excess above
fifteen. The external services and raw field meanings remain separately scoped;
these observations do not define one universal player-price formula.

The final evaluation thresholds are 3.15 for automatic registration and 2.75 for
the requested path. The automatic path has another quote/risk-service sequence
with preserved floating rounding and a single-precision fallback. On acceptance,
the row receives the candidate staff ID, an earlier staff link may be transitioned
and the existing insertion operation is called. Dependencies can change fields;
the original rereads are kept, including a tested change to row+4 during an
assessment callback.

The requested operation accepts a signed-byte apply flag in r7. Zero still
allows a successful assessment, but skips final row publication and link
insertion. This is not a pure query guarantee: scratch globals and dependency
calls can have other effects. The complete operation and those effects are
compared on both flag paths.
