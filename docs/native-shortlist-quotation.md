## Observed behavior

The contextual evaluator receives an object in r3, staff in r4, the considered
club in r5, an enabling mode byte in r6, a requested category in r7, and an
optional reason-word pointer in r8. It clears the supplied reason word before
eligibility checks. Complete paths combine category, profile, current-club,
country, competition, relationship, contract and date/history information.
Some conditions return early. The floating result is returned in f1.

The optional financial refinement requires the enabling byte and an existing
score of at least 1.75. It initializes local scratch, resolves a financial
context, invokes the selected quotation child, and compares the quotation with
additional financial services before returning the adjusted score.

The quotation child consumes the staff, club and scalar options. Its entry r3
is overwritten before use; no output-record contract is inferred from the
caller's scratch argument. It consults contract services and profile fields,
chooses category baselines, applies club and country curves, clamps and explicit
single-precision rounding, and returns f1. Global scratch effects, diagnostic
formatting and random-service calls remain observable parts of the operation.
The precise interface meanings of raw profile fields, option codes and reason
bits remain under investigation. No fee or salary label is inferred merely
from a raw offset.

The modern implementation uses named C++ stages and native conditionals. It has
no instruction interpreter, opcode/PC dispatcher or replay of either original
body. Local arithmetic support preserves recorded signed division and the
single-rounding order of product-difference expressions. Shared guest-call
support is unchanged.
